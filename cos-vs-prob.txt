# Step 5 (Theory): Why Cosine Similarity ≠ Probability / Accuracy

You got a cosine score like:

```
0.46
```

And you are tempted to think:

> “0.46 means 46% correct”

But this is **conceptually wrong**. Here is why.

---

## 1. What Cosine Similarity Actually Is

Cosine similarity measures:

> The **angle** between two vectors in high-dimensional space.

Formula:

[
\cos(\theta) = \frac{A \cdot B}{||A|| , ||B||}
]

It answers only one question:

> Are the two meanings pointing in the same semantic direction?

It does **NOT** answer:

* How likely is this sentence true?
* How confident is the model?
* What is the probability of correctness?

It only answers:

> How aligned are their meanings geometrically?

So cosine is a **geometric measure**, not a **statistical probability**.

---

## 2. Why Cosine Values Stay Low Even for Correct Meaning

In language:

Two sentences can mean the same thing but be expressed very differently:

Prediction:

> He will betray his friend to gain power.

Story:

> He chose ambition over friendship and left the village to become a ruler.

No word overlap:

* betray ≠ chose ambition
* friend ≠ friendship
* power ≠ ruler

So their vectors are:

* In the same general semantic direction
* But not pointing exactly the same way

Hence angle is not very small → cosine is not near 1.

So:

```
cosine ≈ 0.45
```

still means:

> Same event, different abstraction level.

---

## 3. Why Cosine Is Not a Probability

A probability must satisfy:

1. Range 0 to 1
2. Sum to 1 across alternatives
3. Represent likelihood of truth

Cosine:

* Does not sum to 1
* Has no distribution
* Has no notion of "correct" vs "incorrect"
* Only measures **closeness in vector space**

So saying:

> “Cosine = 0.46 means 46% chance correct”

is mathematically invalid.

---

## 4. Real Research Example

In BERTScore (Google / HuggingFace):

| Cosine | Interpretation                   |
| ------ | -------------------------------- |
| 0.90   | Near duplicate                   |
| 0.75   | Strong paraphrase                |
| 0.60   | Same meaning, different phrasing |
| 0.45   | Same event, abstract wording     |
| 0.30   | Weak topical relation            |

So your:

```
0.46
```

means:

> The prediction and story describe the same semantic event at different abstraction levels.

Which is **exactly what a prediction system should detect.**

---

## 5. Why Humans Think in Probability but Models Don’t

Humans think:

> “Is this correct? Yes or No. How confident am I?”

Models think:

> “How aligned are these two semantic manifolds in vector space?”

Two totally different concepts.

So we add a **calibration layer**:

```
Cosine space  →  Decision space
(geometry)      (human confidence)
```

That is what we did with:

```python
if score >= 0.45:
    verdict = "Correct"
```

---

## 6. Why Forcing 0.9 Is Dangerous

If you force scaling:

```
0.46 → 0.92
```

Then a weakly related sentence like:

> He went to school.
> The boy studied at college.

might become:

```
0.28 → 0.56 → incorrectly "correct"
```

You destroy **precision** and your system becomes unreliable.

In viva, an examiner may ask:

> “Why did you normalize cosine to probability?”

And the only correct answer is:

> “We did not treat cosine as probability. We calibrated it using semantic thresholds based on embedding distribution.”

This is a **very strong academic statement**.

---

## 7. The Right Mental Model

Think like this:

* Cosine similarity = semantic distance measure
* Thresholds = decision boundaries
* Calibration = mapping geometry to human confidence
* Cross-encoder (next step) = probability-like scorer

So pipeline becomes:

```
SBERT cosine  →  Candidate similarity
Cross-Encoder →  Probability-like confidence
```

Only the **cross-encoder** gives something close to “true probability”.
